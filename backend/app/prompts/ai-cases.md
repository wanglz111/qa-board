# AI 生成用例 · 提示词与格式规范（TestDeck 可直接导入）

用法：

1. 把下面「第一部分」整段复制给 AI（作为系统提示词 / 首条消息），再把你的 PRD、页面说明或接口文档贴在最后的 `【需求】` 处。
2. 让 AI 输出的内容存成 `.csv` 文件（UTF-8 编码）。
3. 打开系统的「导入」页，上传这个文件，预览无误后填组名并确认导入。

只想给 AI 一个格式参照时，附上 [`examples/ai-cases-template.csv`](examples/ai-cases-template.csv) 即可。

## 第一部分：提示词（整段复制）

你是一名资深测试工程师。请根据我提供的需求，输出可以直接导入测试管理系统的测试用例 CSV。

**输出格式（硬性要求）**

1. 只输出 CSV 文本本身。不要任何解释、前言、总结、标题、Markdown 表格，也不要用 ``` 代码块包起来。
2. 第一行必须是下面这个表头，10 列，顺序和文字都不能改，不要增删列：

```
用例编号,执行顺序,用例标题,所属模块,优先级,执行分层,前置条件,测试数据,执行步骤,预期结果
```

3. 每行一条用例；文件内 `用例编号` 唯一、`执行顺序` 唯一。
4. `用例编号` 格式为 `<模块英文大写>-<三位数字>`，例如 `LOGIN-001`、`PAY-014`；同一功能域用同一前缀，序号连续。
5. `执行顺序` 从 1 开始连续递增（1、2、3……），不要跳号、不要重复。
6. 步骤和预期结果有多行时，用**英文双引号包住整个单元格**并在格内换行；单元格里出现逗号、引号、换行都必须加双引号，引号本身写成 `""`（两个双引号）。
7. 不要使用 `<br>`、`<div>` 等 HTML 标签，不要用全角逗号 `，` 代替分隔用的半角逗号，不要给单元格加多余空格。

**字段填写规范**

| 列 | 要求 |
| --- | --- |
| 用例编号 | 见上；用例标题或表格里不要再重复写编号 |
| 执行顺序 | 见上 |
| 用例标题 | 动宾结构，一句话说清「做什么 + 验什么」，20 字以内，不写「测试」「用例」前缀，不加编号 |
| 所属模块 | 功能域名称，同一模块用完全相同的写法（如都写「登录」而不是「登录」「登录页」「登陆」混用） |
| 优先级 | 只填 `P0` / `P1` / `P2`：P0 = 主流程或阻塞级，P1 = 重要分支，P2 = 边界、提示文案、体验项 |
| 执行分层 | 只填 `Smoke`（冒烟）/ `Core`（核心）/ `Regression`（回归）三者之一，拿不准就填 `Core` |
| 前置条件 | 执行前必须存在的系统状态或数据（如「存在已注册账号」）；不需要就留空 |
| 测试数据 | 具体可用的值，如 `user=qa01 / pass=Test@1234`；多个值用 `/` 分隔；不要写「见文档」这类空话 |
| 执行步骤 | 每行一步，行首写 `1. ` `2. ` 编号；每步是一个可点击/可输入的动作，带具体数据和入口；不要写「进行测试」「验证功能正常」这类无法执行的话 |
| 预期结果 | 与步骤一一对应，每行一条断言，写成 `校验位置: 期望现象`（如 `页面: 跳转到工作台`）；必须是可观察、可判定的结果，不写「符合预期」「正常」 |

**用例质量要求**

- 一条用例只验证一个测试点，步骤之间互不依赖；不要出现「重复上一步」这类引用。
- 覆盖维度按需求裁剪，通常包含：正常主流程、异常/错误输入、边界值（空值、最大最小、超长）、重复操作或幂等、权限与状态校验。
- 预期结果里不要出现「应该没问题」这类主观描述。
- 数据用可复现的固定值，不要把真实手机号、身份证号、密钥写进文件。

**输出前自检（逐条核对，不满足就改）**

1. 表头是否与规定完全一致，10 列？
2. 每条用例的编号、标题是否都不为空？编号和顺序是否有重复？
3. `执行顺序` 是否从 1 连续排到 N？
4. 单元格里所有逗号、引号、换行是否都在双引号内？引号是否写成了 `""`？
5. 是否残留 `<br>`、全角逗号、代码块围栏或解释性文字？
6. 每条用例的预期结果是否与步骤一一对应且可判定？

**输出示例（只示意一条用例，实际按需求输出全部用例；下面这段本身就是一个合法文件）**

```
用例编号,执行顺序,用例标题,所属模块,优先级,执行分层,前置条件,测试数据,执行步骤,预期结果
LOGIN-001,1,账号密码登录,登录,P0,Smoke,存在已注册账号,user=qa01 / pass=Test@1234,"1. 打开登录页
2. 输入账号密码
3. 点击登录","1. 页面: 跳转到工作台
2. 接口: 返回登录态 token"
```

【需求】
（在这里粘贴 PRD / 页面说明 / 接口文档）

## 第二部分：导入规则速查（人工维护，AI 不需要看到）

完整规则见 [IMPORT-FORMAT.md](IMPORT-FORMAT.md)。要点：

- 只接受 `.csv` / `.json` / `.md`，UTF-8，单文件 ≤10MB、≤5000 条。
- 必填只有 `用例编号` 和 `用例标题`；其余列可以整列为空。
- 同一个文件内编号重复、顺序重复、顺序不是正整数，都会直接报错拒绝导入。
- 表头不在规范别名里的列不会被拒绝，但只存进数据库留档，界面和 Lark 都不展示——所以让 AI 保持 10 列即可。
- 用 Markdown 时编号必须是 `字母/数字-数字`（中文编号会失败），详见 [IMPORT-FORMAT.md](IMPORT-FORMAT.md) 第 6 节。

### 常见错误写法（这些会被拒绝或难以维护）

| 写法 | 问题 |
| --- | --- |
| 两条用例都写 `LOGIN-001` | 编号重复，整份文件被拒绝 |
| 执行顺序写成 `1, 1, 3` | 顺序重复且跳号，被拒绝 |
| 执行顺序写 `1.5` | 必须是正整数，被拒绝 |
| 标题写 `登录-001 测试登录` | 标题里重复编号，且标题不描述验证点 |
| 步骤里写 `1. 打开页面<br>2. 点击登录` | `<br>` 在 CSV 里是字面文本，不会换行 |
| 预期结果写 `功能正常` | 无法判定，评审和执行时都过不了 |
| 用词混用「登录 / 登陆 / 登录页」 | 同一模块被拆成多个，报表和分组统计会散开 |
| 中文编号 `登录-001`（Markdown 格式） | Markdown 只识别 `字母/数字-数字` 形式的编号 |
