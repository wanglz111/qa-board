# 测试用例导入格式规范

这份文档是「让 AI 生成用例文件 → 直接在系统里导入」的唯一约定。导入入口：**导入** 页 → 选择文件 → 预览 → 填组名 → 确认导入。

## 1. 支持的文件

| 后缀 | 说明 | 建议 |
| --- | --- | --- |
| `.csv` | 一行一条用例，UTF-8（带 BOM 也可以） | ✅ 首选，AI 最不容易写错 |
| `.json` | 顶层数组，或 `{"cases": [...]}` | 需要结构化多行步骤时用 |
| `.md` / `.markdown` | 每个用例一个 H4 + 字段表 | 需要人读文档时用 |
| `.zip` | 带图用例包：根目录只有 `casebook.json` + `assets/`，文件名（去扩展名）就是图片 key | 用例要和设计稿原型图一起看时用 |

其它后缀（`.xlsx`、`.txt` 等）会被拒绝。文本文件上限 **10 MB**、**5000 条用例**；带图用例包 ZIP 上限 **100 MB**（解压后 ≤ 250 MB，单张图 ≤ 20 MB）。超限报错。

## 2. 字段字典

导入器层面只有 **用例编号** 和 **标题** 是必填，其余列缺省不会报错。但**让 AI 生成文件时，`优先级` 和 `执行分层` 必须逐行填写**（见第 7 节的提示词模板）：这两列漏写不会报错，只会静默落成空值——Lark 执行表的「优先级」会兜底成 `P2`，执行分层在界面和导出报表里则直接是空的。

| 规范字段 | 中文表头 | 可在文件里使用的别名 | 必填 |
| --- | --- | --- | --- |
| code | 用例编号 | `code` `id` `编号` | ✅ |
| title | 用例标题 | `title` `标题` | ✅ |
| position | 执行顺序 | `position` `order` `顺序` `序号` | 否（缺省按文件出现顺序） |
| module | 所属模块 | `module` `模块` | 否 |
| layer | 执行分层 | `layer` `分层` | 否；**AI 生成时必须填**，且只能是英文枚举 `Smoke` / `Core` / `Regression` |
| priority | 优先级 | `priority` | 否；**AI 生成时必须填**，且只能是 `P0` / `P1` / `P2` |
| preconditions | 前置条件 | `preconditions` `precondition` | 否 |
| test_data | 测试数据 | `test_data` `testData` | 否 |
| steps | 执行步骤 | `steps` `步骤` | 否 |
| expected | 预期结果 | `expected` `checkpoints` `预期` | 否 |

表头名不在上表里也能导入：它会出现在导入预览的「字段映射」下拉框里，需要时手工映射到编号／标题／顺序，其余列只做留档，界面和 Lark 都不会展示。

## 3. 硬性校验（不满足会直接报错）

- 文件必须是合法 UTF-8；CSV 的引号必须闭合。
- 每条用例 `用例编号`、`用例标题` 非空。
- **同一文件内**编号不能重复，`执行顺序` 也不能重复。
- `执行顺序` 必须是正整数，或写成 `第 12 条`／`12`；不接受 `1.5`。
- 空行会被自动跳过；整份文件解析不出用例会报「未识别到用例边界」。
- JSON 里不接受 `NaN`／`Infinity`。

## 4. CSV 模板（推荐）

```csv
用例编号,执行顺序,用例标题,所属模块,优先级,执行分层,前置条件,测试数据,执行步骤,预期结果
LOGIN-001,1,账号密码登录,登录,P0,Smoke,存在已注册账号,user=qa01 / pass=***,"1. 打开登录页
2. 输入账号密码
3. 点击登录","1. 进入工作台
2. 生成登录态"
LOGIN-002,2,密码错误登录,登录,P1,Smoke,已注册账号,密码=wrong,"1. 打开登录页
2. 输入错误密码
3. 点击登录","1. 停留在登录页
2. 提示密码错误"
```

要点：

- 步骤有多个时，用**双引号包住整格**并在格内换行（如上），别写 `<br>`——CSV 不解析 `<br>`，那会变成字面文本。
- 单元格里出现逗号或换行就必须加双引号；双引号本身写成 `""`。
- 列的顺序随便，表头名字按第 2 节的别名写就行；多余的列（如 `端`、`图片`）可以留，但只做留档。

## 5. JSON 模板

```json
[
  {
    "用例编号": "LOGIN-001",
    "执行顺序": 1,
    "用例标题": "账号密码登录",
    "所属模块": "登录",
    "优先级": "P0",
    "前置条件": "存在已注册账号",
    "测试数据": "user=qa01 / pass=***",
    "执行步骤": ["1. 打开登录页", "2. 输入账号密码", "3. 点击登录"],
    "预期结果": [
      { "label": "跳转", "text": "进入工作台" },
      { "label": "会话", "text": "生成登录态" }
    ]
  }
]
```

`执行步骤` 数组会按行拼接；`预期结果` 数组元素写成 `{label, text}` 会拼成 `label: text`，也可以直接写字符串数组或一整段字符串。

## 6. Markdown 模板

````markdown
# 登录模块用例

#### LOGIN-001 · 账号密码登录

| 项 | 内容 |
| --- | --- |
| 用例编号 | LOGIN-001 |
| 执行顺序 | 1 |
| 所属模块 | 登录 |
| 优先级 | P0 |
| 前置条件 | 存在已注册账号 |

**执行步骤**

1. 打开登录页
2. 输入账号密码<br>点击登录

**预期结果**

| # | 断言位置 | 预期结果 |
| --- | --- | --- |
| 1 | 跳转 | 进入工作台 |
| 2 | 会话 | 生成登录态 |
````

Markdown 的额外约束（违反会报错，AI 生成时最容易踩）：

- 每个用例**恰好一个** `####` 标题，格式 `#### <编号> · <标题>`（分隔符是 `·` 或空格）。
- 编号必须匹配 `字母/数字 - 数字` 的形式，例如 `LOGIN-001`、`B-014`、`TC-1-2`；**纯中文编号（如 `登录-001`）不被识别**。
- 紧跟一个 **2 列**字段表，表头第一格必须是 `字段`、`项` 或 `Field`。
- 正文里不要再出现其它 `####` 标题配字段表，也不要在用例之间插入 H4 小标题，会判定「用例边界歧义/不完整」。
- `**执行步骤**`、`**预期结果**` 两个加粗小节要独占一行；`<br>` 会转成换行；表格里的 `|` 要写成 `\|`。
- 步骤行开头的 `1.`／`1)` 序号会被自动去掉，只保留文字。
- 全文只走一种风格：要么全是 H4 + 字段表，要么全是一张「编号/标题/步骤/预期」四列表格，混用会报错。

## 7. 交给 AI 的提示词模板

> 按 `docs/IMPORT-FORMAT.md` 生成 CSV，列固定为：用例编号,执行顺序,用例标题,所属模块,优先级,执行分层,前置条件,测试数据,执行步骤,预期结果。每个用例编号唯一且形如 `模块-三位数字`，执行顺序从 1 连续递增，多步骤用双引号包住整格的换行写法，只输出 CSV 内容，不要额外解释。`优先级` 只能 `P0`/`P1`/`P2`，`执行分层` 只能英文枚举 `Smoke`/`Core`/`Regression`（不要写「冒烟层 / 核心层 / 完整层」，也不要写「高/中/低」）；这两列**每一行都必须有值**，不能留空，也不能整列省略——漏写不会报错，只会静默变成空值。

## 8. 图片：当前支持到哪一步

结论：**用例文件本身不支持图片**，图片只存在于「执行结果」这一层。细节和三种组织方式见下方。

### 8.1 导入不认图片

- 字段表里没有图片/附件列；`图片`、`截图` 这类列会被当作普通留档列存进数据库的 `raw`，界面和 Lark 都不展示。
- Markdown 里写 `![截图](images/a.png)` 不会被渲染，只会原样变成 `执行步骤` 里的一串文本；网络 URL 也一样，用例详情页是纯文本展示，不是超链接也不是图片。
- 所以：**别把图片塞进导入文件**，也别指望本地相对路径能在系统里打开。

### 8.2 系统真正支持的图片能力（执行结果截图）

- 位置：执行页保存结果时「添加截图」，或直接把剪贴板图片粘进表单。
- 一条执行记录（attempt）可以挂 **多张**图片，格式限 PNG / JPEG / WebP，单张 ≤ 20 MB，上传后按随机文件名存在服务端 `UPLOAD_DIR`，通过 `/api/screenshots/{id}` 私有读取。
- 目前的短板：执行历史界面不展示这些截图（报表只统计 `screenshot_count`）；同步到 Lark 时 `截图` 字段写空数组，即截图**不会**进 Lark 的附件字段（旧 Lark 记录里的截图倒能读回来展示，是只读的）。

### 8.3 带图样例的三种组织方式

1. **纯文本用例 + 执行时补图**（今天就能用）：导入文件只写文字用例，把截图在执行页作为 result 截图上传。适合「图是执行证据」的场景。
2. **URL 写进文本字段**（今天就能用，只做参考）：把图片 URL 放进 `测试数据`／`执行步骤`／`预期结果`，导入后原文保留，但只能看到一串链接文本，Lark 也不会带图。适合图放在外部图床、人工点开看的场景。
3. **把图作为用例的一部分导入**（已经做好）：用 §9 的 casebook 用例包（`casebook.json` + `assets/`）导入，图片按组去重存进服务端，用例详情页和执行页显示「目标核对图 / 定位辅助图 / 核图重点 / 不应出现」。图片不会写进 Lark 附件字段，Lark 上传附件能力仍未实现。

如果图是「用例的组成部分」（比如设计稿对照、字段标注），选 3；如果图只是「跑出来的证据」，选 1，成本最低。

## 9. 带原型图的用例包（ZIP）

要把「用例 + 设计稿图片」一起导入，用 casebook 用例包：

```text
odyssey-casebook.zip
├── casebook.json
└── assets/
    ├── sale-stage-selling.png
    └── sale-confirm-modal.png
```

- 文件名（去扩展名）就是 asset key，没有第二份 manifest；引用不存在的 key 会整包拒绝。
- 完整字段与严格校验规则见 [CASEBOOK-FORMAT.md](CASEBOOK-FORMAT.md)。
- 让 AI 把现有用例改写成这个格式：用 [AI-CASEBOOK-PROMPT.md](AI-CASEBOOK-PROMPT.md) 或在导入页点「复制提示词」。
- 图片需要你自己从设计稿导出；AI 只写 JSON。
- 导入后执行页按用例显示：目标核对图（大图 + 切换 + 放大）、定位辅助图、核图重点、「不应出现」清单；报表里的 `reference_image_count` 与 `screenshot_count` 是两列不同的数字。
